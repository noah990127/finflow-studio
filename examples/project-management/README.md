# 项目协同管理｜会议到周报

项目涵盖客户服务平台、经营数据看板两个项目，6名成员。会议日期为2026年11月26日，负载统计周期为11月30日至12月4日。

## 导入后看到什么

「项目进展看板」包含三个业务步骤：

1. 会议变更整理：已确认变更和待确认事项。
2. 任务台账及双视角：完整台账、项目WBS、人员分工、人员繁忙程度热力图。在该步骤的成果下拉框切换；热力图直接嵌入工序。
3. 项目风险与汇报：风险评估、人员负载对比、6页PPT。

默认导入依据已备资料重新渲染页面与PPT，不调用模型、不伪造模型执行记录。更换会议资料并重新分析，需要额外导入「周会任务更新与风险汇报」完整工序。

## 文件说明

| 文件 | 作用 |
| --- | --- |
| `manifest.json` | 资源逻辑名称、相对路径、SHA-256与验收指标 |
| `inputs/` | 会前/会后Excel、会议口述稿、管理口径、Excel同源JSON、内联样式热力图模板 |
| `outputs/` | 已验证的会后台账、WBS、人员视图、热力图、风险分析与PPT |
| `live-workflow.json` | 完整动态工序；输入使用资源逻辑名称，由导入脚本绑定新环境资源ID |

仅包含本项目资料，不包含账户、模型密钥、本机数据库、聊天历史、浏览器登录态、原项目资源编号或模型配置快照。

## 导入

服务部署、HTTPS、模型设置、离线部署及备份见[内部部署与项目管理数据](../../docs/内部部署与项目管理数据.md)。需要包含通用成果展示和固定工具工序能力的服务版本，旧版服务仅导入数据不能补齐这些功能。

```bash
python3 scripts/import-project-management.py --validate-only
python3 scripts/import-project-management.py \
  --base-url https://studio.example.internal/api --username admin
```

密码由终端交互输入，也可通过临时环境变量 `FINFLOW_IMPORT_PASSWORD` 注入。导入进度写入 `.run/project-management-import.json`，保存该文件后重复同一命令不会重复建项目或重复运行已成功工序。不同服务器、账号或更新的数据包必须使用不同的 `--state`。

追加完整分析工序，仅发布不执行：

```bash
python3 scripts/import-project-management.py \
  --base-url https://studio.example.internal/api --username admin --include-live
```

模型可用后，用 `--run-live` 显式执行完整工序。它会调用模型并产生新成果，可能耗时数分钟。输入更新须同时维护会议稿和对应同源台账；当前流程不是Excel自动双向同步。

## 数据包更新

修改文件后必须同步重新计算 `manifest.json` 对应的SHA-256；调整完整工序需同步 `workflowSha256`。不要在原导入状态文件上强行换包：使用新的项目名和状态文件验证，再由项目负责人决定替换旧项目。历史执行快照保留，不直接修改数据库记录。
