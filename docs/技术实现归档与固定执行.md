# 技术实现归档与固定执行

## 约束

业务工序用于检查成果；技术实现负责执行。SQL、固定提示词和已注册工具调用统一归档为资源，不能用 Agent 的完成声明或 Markdown 说明替代可执行实现。

发布时创建实现清单和每个技术步骤的代码资源；绑定资源 ID、版本及 SHA-256。执行器读取这些固定版本并校验内容。用户编辑资源生成的新版本不会自动替换已发布实现，逻辑变更需要重新发布。旧定义在下一次开始前显式归档，缺失或校验失败则拒绝执行。

## 代码结构

- `TechnicalArtifactService`：固定版本资源索引、代码与清单归档、完整性验证。
- `FixedWorkService`：发布、输入快照、从归档实现执行、业务工序与技术步骤对应关系。
- `TechnicalExecutionJournal`：调用前登记 DISPATCHING；返回后登记 SUCCEEDED 和输出资源；未取得明确结果标为 NEEDS_VERIFICATION，不推断外部操作未发生。
- `BrowserAgentService`：锁定浏览器脚本资源版本并传给 browser-use；保留账号、工作及网站授权检查。多道工序没有显式映射时不再归到最后一道工序。
- `TechnicalArchiveReconciler`：后台查询任务结果、补归档及发布；只重试持久化，不重新提交业务操作。服务启动默认 60 秒后开始，每轮结束 15 秒后继续，逐批处理并轮换失败任务。
- `ResourceVisibilityService`：技术实现和执行记录默认不出现在业务资源目录；显式业务输入或成果声明仍优先。
- `WorkExecution.vue`：只在已有技术详情内显示资源链接和按需加载的步骤执行记录。

`technical_artifact` 保存资源归属和固定版本；`technical_step_execution` 保存每轮实际执行；浏览器任务保存归档完成状态、最近检查时间和失败原因。后台按任务所属账号执行归档，详情接口按项目和工作校验访问权限。

浏览器重放请求携带 `replay_bundle`。Python 校验 bundle 哈希、参数契约并保持原审批策略，再交给既有 browser-use 重放引擎。平台路径不再依赖临时 `.procedure.json`；Python 的旧直接客户端仍保留本地文件兼容路径。

## 当前边界

- 平台级记录以已发布技术步骤为单位；浏览器内部动作保存在脚本 bundle 中，并不冒充为已拆分的多道业务工序。
- 一次自由探索的成功轨迹不保证可泛化为所有条件分支。未能编译或缺少绑定的轨迹保留待整理状态，不自动发布。
- 目前固定执行仍是顺序步骤，不支持任意循环或条件分支；工具仍需加入既有固定工具契约，不能执行任意工具名称。
- 重启后不自动恢复未知外部提交。登录等人工等待可在当前存活任务内继续，但本次没有实现跨进程浏览器动作断点恢复。
- 后台归档已不依赖用户打开详情；现有状态查询仍保留幂等的及时归档逻辑，不是纯只读接口。
- 执行逻辑和输入版本可追溯，不承诺外部网页稳定或模型输出逐字一致。
- 新增数据库结构和 Java/Python 逻辑需重启对应服务后生效；不要在未核验的外部提交期间重启浏览器服务。

## 验证

Java 测试覆盖固定代码版本、输入变化、完整性校验、技术资源隐藏、后台重试和既有工序行为。Python 测试覆盖从归档 bundle 执行（原临时文件不存在）及固定审批策略。测试使用替身工具，不发送邮件。
